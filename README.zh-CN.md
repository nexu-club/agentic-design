## ✨ Open Design 是什么？

**Open Design 是一个以聊天为入口、以 Agent 为队友的设计工作空间，覆盖从 PRD 到设计稿到线上产品的完整生命周期。**

传统工具把同一个产品切成碎片：**Figma + Jira + GitHub + Slack + Notion + Linear + 一堆文档 Wiki**。每一次交接都在丢失上下文，每一个新人都要重新摸索。

**Open Design 把这一切收敛到一件事：一个群聊，人和 Agent 在里面共同打造一个会长大的产品。**

- 💬 **群聊即入口** —— PRD、设计稿、原型、发版记录、用户反馈都走同一条主线
- 🤖 **Agent 是队友，不是工具** —— 设计 Agent、PM Agent、测试 Agent、增长 Agent 都可以被 @
- 🎨 **设计是中心** —— 可视化产物是事实源头，不是文档
- 🚀 **一键上线** —— 原型直接变成线上网页
- 📊 **数据回流** —— 用户分析直接回到同一个群里，喂养下一轮迭代

## 🌱 我们为什么做这个

> *"Figma 是为人类独自设计的世界造的。我们是为人类和 Agent 一起设计的世界造的。"*

我们面向 146 位 builder 做了产品调研（94 个合格 ICP）。用户最想要的 Top 3 能力：

1. **"Agent 之间互相分配任务"** —— 71%（能力需求榜第一）
2. **"所有 Coding Agent 在一个地方"** —— 60%
3. **"7×24 后台跑的 Agent，不用人盯着"** —— 60%

而用户自己在主观题里说的最扎心的一句话：

> *"需要一个能共生共成长的数字孪生伙伴，一个可以在同一个空间协同的多智能体蜂群。"*

Open Design 就是为了回答这句话。

## 🧭 产品原则

1. **默认可用 > 可配置** —— 每一个 onboarding 步骤都在消耗用户容忍度，我们对抗"配置地狱"
2. **聊天驱动协同，文件承载收敛** —— 聊天是怎么配合的，文件是最终结论
3. **把用户的原话还给用户** —— 产品的文案要用用户自己已经在说的词
4. **Open core, managed edges** —— 源码免费开源；编排、Token 路由、协作是商业化服务
5. **设计先行，再扩展全栈** —— 我们从设计切入（上下文最具象的地方），再逐步往 PRD / 构建 / 发布 / 数据扩

---

## 🧩 这是给谁用的？

- **独立开发者 / OPC 一人公司** —— 你需要一群 Agent 围着你
- **2–50 人小产品团队** —— 受够了工具散乱
- **设计团队** —— 要的是 AI 队友，不是 AI 插件
- **工程团队** —— 在做 Agent 原生产品，需要设计到生产的闭环

## 🗺️ 路线图

Open Design 分 4 个阶段。我们有意**窄而深**起步，再扩展。

### 阶段 1 · 单机设计（现在 → 2026 Q2）
- 🖼️ Web 画布 —— 通过聊天创建和迭代设计
- 🤖 内置设计 Agent（布局 / 组件 / 文案 / 图标）
- 📄 PRD 转设计 —— 粘贴规格，生成初稿
- 🧠 持久记忆 —— Agent 记住你的设计系统

### 阶段 2 · 桌面端 & 本地优先（2026 Q3）
- 💻 桌面应用（macOS / Windows / Linux）
- 📁 本地文件库 + Git 友好的设计文件
- 🔌 MCP + 插件生态

### 阶段 3 · 多人协作（2026 Q4）
- 👥 群聊就是设计室
- 🧑‍🤝‍🧑 人和 Agent 同等权限共同编辑
- 🔍 可搜索的设计历史 & 决策
- 🔀 设计评审工作流

### 阶段 4 · 全产品生命周期（2027）
- 📝 PRD ↔ 设计 ↔ 原型 ↔ 上线 ↔ 数据 —— 一条聊天线打通
- 🚀 一键部署到线上
- 📈 线上数据直接回到设计群
- 🏭 拓展到相邻流程（营销素材、品牌系统、甚至生产制造）
